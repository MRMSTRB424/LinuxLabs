# Лабораторная работа № 1. Установка Debian на виртуальную машину и настройка SSH

## Цель работы

Установить гипервизор VirtualBox, создать виртуальную машину с Debian, настроить сетевые подключения (NAT и Bridged), обновить систему и настроить удалённый доступ по SSH (по паролю и по ключу).

## Используемые средства

| Компонент | Версия |
|---|---|
| Гипервизор | Oracle VirtualBox 7.2.22 |
| Гостевая ОС | Debian 13.7.0 «Trixie» (amd64, netinst) |
| Хост-система | Windows |

---

## 1. Установка виртуальной машины

### 1.1. Установка VirtualBox

Установщик VirtualBox версии 7.2.22 скачан с официального сайта [virtualbox.org](https://www.virtualbox.org/wiki/Downloads) (пакет для Windows hosts).

![Страница загрузки VirtualBox](images/virtualbox-download.png)

### 1.2. Создание виртуальной машины

С сайта [debian.org](https://www.debian.org/distrib/) скачан образ `debian-13.7.0-amd64-netinst.iso`. В VirtualBox создана новая виртуальная машина: указаны имя, папка ВМ и путь к ISO-образу. VirtualBox автоматически определил тип ОС (Linux, Debian 13 Trixie, 64-bit) и предложил выполнить автоматическую установку.

![Имя ВМ и образ ISO](images/vm-name-iso.png)

Для автоматической установки заданы параметры гостевой ОС:

| Параметр | Значение |
|---|---|
| Имя пользователя | `vboxuser` |
| Имя хоста (hostname) | `linux` |
| Имя домена | `myguest.virtualbox.org` |

![Пользователь и имя хоста](images/vm-user-hostname.png)

Выделены ресурсы виртуальной машины:

| Ресурс | Значение |
|---|---|
| Оперативная память | 4096 МБ |
| Процессоры | 2 |
| Жёсткий диск | 30 ГБ |

![Виртуальное оборудование](images/vm-hardware.png)

## 3. Настройка сети и обновление системы

### 3.1. Режим Bridged (сетевой мост)

В настройках ВМ: **Сеть → Адаптер 1 → Тип подключения: Сетевой мост**. В качестве адаптера выбран физический Wi-Fi адаптер хост-системы (Intel Wi-Fi 6 AX200). В этом режиме ВМ получает IP-адрес из локальной сети (в работе получен адрес `192.168.0.102`).

![Сеть: режим Bridged](images/network-bridged.png)

### 3.2. Обновление системы

Выполнено обновление списка пакетов и установленных пакетов:

```bash
sudo apt-get update
sudo apt-get upgrade
```

Репозитории `trixie`, `trixie-security` и `trixie-updates` доступны, обновлять нечего: система уже содержит актуальные версии пакетов.

![apt-get update и upgrade](images/apt-update-upgrade.png)

### 3.3. Режим NAT

В настройках ВМ: **Сеть → Адаптер 1 → Тип подключения: NAT**. В этом режиме ВМ выходит в интернет через хост-систему (адрес в ВМ `10.0.2.15`), но подключиться к ней напрямую из локальной сети нельзя, поэтому для SSH настроен проброс порта.

![Сеть: режим NAT](images/network-nat.png)

### 3.4. Проброс порта для режима NAT

Настроено правило: **Сеть → Адаптер 1 → Дополнительно → Проброс портов**.

| Имя | Протокол | Адрес хоста | Порт хоста | Адрес гостя | Порт гостя |
|---|---|---|---|---|---|
| Rule 1 | TCP | 127.0.0.1 | 2222 | (пусто) | 22 |

Обращение к `127.0.0.1:2222` на хост-системе перенаправляется на порт 22 внутри виртуальной машины.

![Проброс портов](images/port-forwarding.png)

## 4. Настройка SSH

### 4.1. Установка SSH-сервера

```bash
sudo apt-get install openssh-server -y
```

Пакет `openssh-server` уже был установлен вместе с системой, поэтому установщик сообщил, что установлена последняя версия.

![Установка openssh-server](images/install-openssh.png)

Включён автозапуск службы и она запущена:

```bash
sudo systemctl enable --now ssh
```

![Включение службы ssh](images/enable-ssh.png)

Проверка статуса службы:

```bash
sudo systemctl status ssh
```

Служба имеет статус `active (running)` и принимает подключения на порту 22.

![Статус службы ssh](images/ssh-status.png)

### 4.2. Подключение по паролю

Подключение выполнено с основного компьютера (Windows) к виртуальной машине через проброшенный порт NAT:

```bash
ssh -p 2222 vboxuser@127.0.0.1
```

При первом подключении подтверждён отпечаток ключа сервера (`yes`) и введён пароль пользователя `vboxuser`. Приглашение `vboxuser@linux:~$` подтверждает успешный вход.

![Подключение по паролю](images/ssh-password-login.png)

### 4.3. Подключение по ключу

На основном компьютере сгенерирована пара ключей:

```bash
ssh-keygen -t ed25519 -C "vboxuser@lab"
```

Публичный ключ добавлен в файл `~/.ssh/authorized_keys` на виртуальной машине (командная строка Windows):

```cmd
type %USERPROFILE%\.ssh\id_ed25519.pub | ssh -o PubkeyAuthentication=no -p 2222 vboxuser@127.0.0.1 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
```

Теперь вход выполняется по ключу, пароль пользователя ВМ не запрашивается. Запрашивается только парольная фраза самого приватного ключа, которая была задана при его создании.

```bash
ssh -p 2222 vboxuser@127.0.0.1
```

![Подключение по ключу](images/ssh-key-login.png)

## Вывод

В ходе лабораторной работы был установлен VirtualBox 7.2.22, создана виртуальная машина (4096 МБ ОЗУ, 2 процессора, диск 30 ГБ) и установлена ОС Debian 13. Были настроены сетевые режимы NAT и Bridged, выполнено обновление системы командами `apt-get update` и `apt-get upgrade`. Установлен и запущен SSH-сервер, настроен проброс порта 2222 → 22 для режима NAT и выполнен доступ с основного компьютера к виртуальной машине по паролю и по SSH-ключу.
